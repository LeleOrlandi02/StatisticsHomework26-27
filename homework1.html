1. Parameters & Base Point Selection

Select the finite field prime modulus $p$, choose the generator base point $G$, and specify the private scalar key $k$.

2. Public Key Computation Results

Evaluating scalar point multiplication $Q = kG$ and comparing naive repeated addition against fast double-and-add.

A Repeated Addition: G, 2G, 3G, …, kG
Linear Complexity O(k)

Iteratively computes $(i)G = (i-1)G + G$ for $i = 2, \dots, k$. Requires $k - 1$ elliptic curve point additions.

B Fast Method: Double-and-Add
Logarithmic Complexity O(log k)

Inspects the binary expansion of $k$. For each bit, doubles the current accumulator point, and adds $G$ if the bit is $1$. Drastically reduces operation count from $k-1$ to at most $2 \lfloor \log_2 k \rfloor$ point operations.

3. Slow-Motion Chord-and-Tangent Interactive Animation

Visualizing the geometric chord-and-tangent law over the modular lattice $\mathbb{F}_{17}$: the line through $P$ and $Q$ meets the curve at a third point $R$, and $P + Q$ is the reflection of $R$ across the x-axis ($y \mapsto p - y$).

4. Empirical Statistical Exploration

Computes $Q_k = kG$ across the entire subgroup $k = 1 \dots n-1$. Evaluates coordinate histograms, bit frequencies, Pearson correlation, Strict Avalanche Criterion (SAC), and brute-force ECDLP hardness.

5. Theoretical Discussion: One-Way Function ($k \mapsto kG$) vs. Hash Function

A rigorous conceptual comparison between the mathematical trapdoor of scalar multiplication and the pseudorandom compression of cryptographic hash functions.

🔑

Sensible Properties of a One-Way Function

$k \mapsto kG$ on Elliptic Curves
  • Cost Asymmetry: Forward multiplication costs $O(\log k)$ via double-and-add; backward inversion is the Elliptic Curve Discrete Logarithm Problem (ECDLP). Note: security is not measured by statistical uniformity, but by the hardness of the ECDLP ($O(\sqrt{n})$ Pollard's rho).
  • Subgroup Injectivity: For $k \in [1, n-1]$, every private key maps to a unique point on the subgroup (no collisions). The map does not compress; collision resistance is key uniqueness.
  • Uniformity in the Subgroup: If private key $k$ is chosen uniformly at random, public point $Q$ is perfectly uniform among all points generated by $G$ (bijective mapping).
  • Intended Algebraic Group Structure: Satisfies $Q_{k_1 + k_2} = Q_{k_1} + Q_{k_2}$ and $x(Q_k) = x(Q_{n-k})$. These homomorphic relations are essential for signatures (ECDSA), Diffie-Hellman (ECDH), and public key recovery.
  • Inversion Difficulty: ECDLP ($O(\sqrt{n})$)
  • Group Homomorphism: Present by design
  • Ethereum Primitive: secp256k1 (Digital Signatures)
⚡

Typical Hash Function Properties

Not Required of Scalar Multiplication ($kG$)
  • Strict Avalanche Criterion (SAC): Flipping a single input bit changes ~50% of output bits independently. For $kG$, this is neither guaranteed nor required: consecutive keys $k$ and $k+1$ yield points differing by $+G$.
  • Pseudorandomness on Bit Strings: Hash outputs must be indistinguishable from random bits. By contrast, curve points have strict algebraic constraints: $x < p$, only ~half of $x$ admit points on the curve, and $y^2 = x^3 + 7 \pmod p$.
  • Compression & Arbitrary Input: A hash function compresses variable-length messages into a fixed digest ($256$ bits) with preimage and second-preimage resistance. $kG$ does not compress.
  • Absence of Homomorphisms: A good hash must have no linear or algebraic relations ($H(a \oplus b) \ne H(a) \oplus H(b)$). For $kG$, group structure is fundamental.
  • Strict Avalanche (SAC): Not required of $kG$
  • Bit Independence: Subject to $y^2 = x^3 + 7$
  • Ethereum Primitive: Keccak-256 (Compression)
🛡️

The Division of Labor in Ethereum

Why We Need Both Primitives

This theoretical distinction directly explains the architecture of Ethereum wallets:

  • secp256k1 ($k \mapsto kG$) provides the mathematical trapdoor required for asymmetric authorization: users sign transactions with private key $k$, and the EVM verifies the signature against public key $Q$.
  • Keccak-256 ($Q \mapsto \text{Address}$) takes the 64-byte public key coordinates, strips all algebraic structure, compresses the data into a 20-byte digest, and destroys mathematical homomorphisms to safeguard storage and privacy.
  • Public Key Role: Authorization & Signatures
  • Hash Function Role: Compression & Obfuscation
  • Combined Pipeline: Entropy → $k$ → $Q$ → Hash → Address
